# AGENTS.md — TanStack Start Starter

## Project Overview

TanStack Start SSR app deployed on Cloudflare Workers. Uses file-based routing, server functions for backend logic, Drizzle ORM for database access, and TanStack Query for data fetching. Supports English and Chinese (zh-CN) with URL-based locale routing.

## Tech Stack

| Layer | Library | Notes |
|-------|---------|-------|
| Framework | React 19, TanStack Start | SSR on Cloudflare Workers |
| Routing | TanStack Router (file-based) | `src/routes/`, auto-generated `routeTree.gen.ts` |
| Data Fetching | TanStack Query 5 | SSR integration via `@tanstack/react-router-ssr-query` |
| Forms | TanStack Form 1 | Field helpers pattern |
| Database | Drizzle ORM + libsql (SQLite/Turso) | `src/db/` schema, libsql client |
| Styling | Tailwind CSS v4 + shadcn/ui | CSS variables in `globals.css`, 23 UI components |
| Linting/Format | Biome 2 | `biome check` and `biome format` |
| Testing | Vitest | `vitest run` |
| TypeScript | TypeScript 6 (strict mode) | `verbatimModuleSyntax`, `noUnusedLocals` |
| React Compiler | babel-plugin-react-compiler | Enabled via `@vitejs/plugin-react` compiler preset |
| Package Manager | Bun | Scripts use `bun run` |

## Routing Conventions

### File-Based Routes

Routes are files in `src/routes/`. The router auto-generates `routeTree.gen.ts`.

```tsx
// src/routes/about.tsx
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/about')({
  component: About,
})

function About() {
  return <main>About page</main>
}
```

### Root Layout

`src/routes/__root.tsx` uses `createRootRouteWithContext<RouterContext>()`. It provides:
- `<html>` shell with locale-aware `lang` attribute
- `<ThemeProvider>` (next-themes) wrapping the app
- `<TooltipProvider>` (shadcn/ui tooltip)
- `<I18nProvider>` with locale and translation function from route context
- `<Header>` and `<Footer>`
- `<Toaster>` (sonner toast notifications)
- Devtools: TanStack Router, React, and TanStack Query panels

The root route uses `beforeLoad` to set locale and translation function:

```tsx
export const Route = createRootRouteWithContext<RouterContext>()({
  beforeLoad: () => {
    const locale = getCurrentLocale()
    return { locale, t: createT(locale) }
  },
})
```

### Route Loaders

Use loaders for data prefetching on the server:

```tsx
export const Route = createFileRoute('/demo/drizzle')({
  component: DemoDrizzle,
  loader: async () => await getTodos(),
})
```

Access loader data with `Route.useLoaderData()`.

### Link Components

```tsx
import { Link } from '@tanstack/react-router'
<Link to="/about" activeProps={{ className: 'font-semibold' }}>About</Link>
```

## Server Functions

Write backend logic in route files using `createServerFn`:

```tsx
import { createServerFn } from '@tanstack/react-start'

// GET (server-rendered or client-called)
const getTodos = createServerFn({ method: 'GET' }).handler(async () => {
  return await db.query.todos.findMany({ orderBy: [desc(todos.createdAt)] })
})

// POST with validation
const createTodo = createServerFn({ method: 'POST' })
  .validator((data: { title: string }) => data)
  .handler(async ({ data }) => {
    await db.insert(todos).values({ title: data.title })
    return { success: true }
  })
```

After mutation, invalidate the router to refetch loader data:

```tsx
const router = useRouter()
await createTodo({ data: { title } })
router.invalidate()
```

## Data Fetching (TanStack Query)

The app uses the SSR query integration from `@tanstack/react-router-ssr-query`. A `QueryClient` is created per-request in `router.tsx` and wired via `setupRouterSsrQueryIntegration`.

For client-side queries within components:

```tsx
import { useQuery } from '@tanstack/react-query'

function MyComponent() {
  const { data } = useQuery({
    queryKey: ['todos'],
    queryFn: () => fetch('/api/todos').then(r => r.json()),
    initialData: [],
  })
}
```

The `RouterContext` includes `queryClient`, making queries available during SSR via loader functions.

## Database Access

### Setup

Database client in `src/db/index.ts`:

```ts
import { createClient } from '@libsql/client'
import { drizzle } from 'drizzle-orm/libsql'
import * as schema from './schema.ts'

const client = createClient({
  url: process.env.DATABASE_URL ?? 'file:dev.db',
})
export const db = drizzle(client, { schema })
```

Default: local SQLite (`dev.db`). Set `DATABASE_URL` in `.env.local` for Turso/remote.

### Schema

```ts
// src/db/schema.ts
export const todos = sqliteTable('todos', {
  id: integer({ mode: 'number' }).primaryKey({ autoIncrement: true }),
  title: text().notNull(),
  createdAt: integer('created_at', { mode: 'timestamp' })
    .default(sql`(unixepoch())`),
})
```

```bash
bun run db:push       # drizzle-kit push
bun run db:pull       # drizzle-kit pull

```

## i18n

### Locales

Two locales: `en-US` (default) and `zh-CN`. Translation files in `src/shared/i18n/locales/`.

### URL-Based Locale Routing

- Default locale (`en-US`) has no URL prefix: `/about`
- Non-default locale gets prefixed: `/zh-CN/about`
- Locale is set from URL in `src/server.ts` (CF Worker entry)
- Router rewrites de-localize URLs internally via `rewrite.input`/`rewrite.output`
- Locale cookie (`starter_locale`) persists the choice

### Usage in Components

```tsx
import { useTranslation } from '#/shared/i18n/hooks'

function MyComponent() {
  const { t, locale } = useTranslation()
  return <h1>{t('pages.settings.title')}</h1>
}
```

### Navigation

```tsx
import { useNavigate, useRouterState } from '@tanstack/react-router'
const navigate = useNavigate()
const pathname = useRouterState({ select: (s) => s.location.pathname })
// Switch locale via URL navigation — handled in LanguageSwitcher
```

## Theme

`next-themes` with `ThemeProvider` wrapping the app in `__root.tsx`. Supports light, dark, and system modes. Persisted to localStorage key `theme`.

```tsx
import { useTheme } from 'next-themes'
const { theme, setTheme } = useTheme()
// Cycles: light → dark → system → light
```

## Styling

### Tailwind CSS v4

Configured via `@tailwindcss/vite` plugin. CSS variables are defined in `src/globals.css` using oklch color space. Dark mode uses `.dark` class variant.

## Key Patterns

### Add a New Route

1. Create `src/routes/my-page.tsx`
2. Run `bun run generate-routes` (or rely on watch mode)
3. Export route with `createFileRoute('/my-page')({ component, loader? })`

### Create a Server Function

```tsx
const myAction = createServerFn({ method: 'POST' })
  .validator((input: { ... }) => input)
  .handler(async ({ data }) => {
    // Server-only code here
  })
```

### Query the Database in a Route

```tsx
// In route file
const getData = createServerFn({ method: 'GET' }).handler(async () => {
  return await db.query.tableName.findMany()
})

export const Route = createFileRoute('/path')({
  loader: async () => await getData(),
  component: MyComponent,
})
```

### Use shadcn/ui Components

Import from `#/components/ui/<name>`:

```tsx
import { Button } from '#/components/ui/button'
import { Card, CardContent } from '#/components/ui/card'
```

### Forms

Use `useAppForm` from `#/hooks/demo.form` with field helpers:

```tsx
const form = useAppForm({
  defaultValues: { title: '' },
  validators: { onBlur: schema },
  onSubmit: ({ value }) => { ... },
})

<form.AppField name="title">
  {(field) => <field.TextField label="Title" />}
</form.AppField>
```

## CF Worker Entry

`src/server.ts` is the Cloudflare Workers entry point. It handles:
- Skipping non-page routes (`/api/`, `/_`)
- Redirecting default-locale-prefixed URLs (`/en-US/about` → `/about`)
- Setting locale cookie for non-default locale URLs

## Deployment

```bash
bun run deploy
```

Requires `wrangler` installed and authenticated. Secrets go through `wrangler secret put`, non-secret env vars in `wrangler.jsonc` under `vars`. KV, D1, R2, and DO bindings configured in `wrangler.jsonc`.
